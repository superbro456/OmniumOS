# Omnium OS (Aurora)

**Модульная гибридная операционная система** с адаптивным ядром **FlexKernel**, зональным управлением ресурсами и глубоко интегрированной многоуровневой безопасностью.


---
## Галактическое ядро (новая основа, ноябрь 2026)

Ядро перестраивается по схеме «галактики». Это не монолит, не микроядро и не гибрид: программы живут в одном адресном пространстве и говорят только через каналы, а права дают только ключи.

| Часть | Что это | Где в коде |
|---|---|---|
| Звезда | диспетчер на каждом ядре CPU, своя очередь, общей очереди и общего замка нет | `kernel/galaxy/star.c` |
| Клетка | программа или сервис: свой стек, своя куча с квотой, своя связка ключей | `kernel/galaxy/star.c` |
| Паёк (ration) | сколько мс подряд клетка работает за круг; это скорость, а не права | `cell_new(..., ration, ...)` |
| Канал | кольцо сообщений между клетками; большие данные едут блоком без копии (move) | `kernel/galaxy/chan.c` |
| Ключ | право на канал: полная проверка один раз при выдаче, потом одно сравнение версии; отзыв = версия+1 | `key_grant`, `key_revoke_all` |
| Схема канала | хеш описания сообщений; ключ с чужой схемой не выдаётся, замена сервиса на несовместимую версию отклоняется | `gx_schema` |
| Горячая замена | старая версия сервиса передаёт новой состояние и ключи, очередь запросов не теряется | `key_pass` |
| Танец звёзд | раз в 10 мс звезда смотрит на соседок и, если у самой загруженной хотя бы на 2 клетки больше, забирает ОДНУ готовую клетку; перешедшая клетка 50 мс отдыхает; драйверы привязаны к своей звезде | `steal_one` |

Три ручки не зависят друг от друга: **орбита** — насколько доверяем коду, **ключи** — что ему можно, **паёк** — сколько ему CPU.

### Проверка

```
make CROSS= galaxy          # QEMU грузит kernel.elf напрямую, GRUB не нужен
make CROSS= SMP=2 galaxy
```

Ядро само запускает проверки и печатает `[Check] ... OK`. Сейчас проходят все:

- паёк 30 и 10 делит ядро CPU как 3 : 1;
- каналы работают на одной звезде и между звёздами;
- блок 64 КБ ездит туда-обратно через move: это тот же блок, без копии;
- клетка с делением на ноль и клетка с неизвестной командой убираются, их каналы закрываются, соседняя клетка на том же ядре CPU работает дальше;
- клетка с квотой кучи 64 КБ получает ровно 4 куска по 16 КБ, потом отказ, а не падение;
- нет ключа, ключ только на чтение, отозванный ключ, ключ с чужой схемой — всё отклоняется;
- танец: 8 занятых клеток рождаются на одной звезде и за 20 мс расходятся по 2 на каждую из 4 звёзд, каждая переходит не больше одного раза;
- горячая замена под нагрузкой: 20 000 запросов, все отвечены, новая версия получила состояние старой; замена на версию с другой схемой отклонена, старая работает дальше.

### Замеры (QEMU без KVM, 4 ядра)

В эмуляторе всё медленнее, чем на железе, поэтому важны не сами наносекунды, а сравнение с базой в том же эмуляторе.

| Что | Время в QEMU |
|---|---|
| вызов функции | ~20–40 нс |
| вход в ядро и выход (как пустой syscall) | ~570–990 нс |
| круг по каналу на одной звезде (2 сообщения + 2 переключения клеток) | ~1,6–3,2 мкс |
| круг по каналу между двумя ядрами CPU | ~2,3–3,5 мкс |
| круг с блоком 64 КБ через move | ~1,8 мкс, как пустое сообщение |
| копия 64 КБ (`kmemcpy`) | ~160–180 мкс |

### Чего ещё нет

- **Защиты памяти между клетками.** Все клетки на Си в кольце 0 и в одном адресном пространстве. Падения CPU (деление на ноль, неизвестная команда) уже изолированы, а кривой указатель может испортить чужую память. Защищать будет компилятор Tachbit (клетки на безопасном языке) или песочница MMU для чужого Си-кода (пояс Койпера).
- Пользовательского режима, IOMMU, драйверов, диска, подписи кода и тайной зоны для ключей.
- Старые модули (Plants, FlexIPC, AI Core, Security Core) пока собираются, но галактика их не использует.

## 1. Философия и цели

Omnium OS проектируется как **платформенная операционная система**, а не просто «ядро + user space».

Система ориентирована на предсказуемость, масштабируемость и безопасность на уровне архитектуры.

### Ключевые цели:

- Детерминированное поведение ядра  
- Масштабируемость от **MONO** до **DISTRIBUTED**  
- Строгая изоляция компонентов без потери производительности  
- Встроенная безопасность как базовое свойство системы  
- Интеграция с кастомной архитектурой **OmniumX**  

---

## 2. Архитектура ядра: FlexKernel

**FlexKernel** — гибридное ядро, объединяющее:

- микроядерный подход (изоляция, IPC, сервисная модель)
- монолитный подход (производительность, низкая латентность)

Ядро разделено на независимые **Core-модули**, каждый из которых выполняет строго определённую функцию.

---

### 2.1 Core-модули ядра

#### Central Core
Главный координатор системы.

Функции:
- управление режимами (**MONO / DISTRIBUTED / EMERGENCY**)
- маршрутизация системных событий
- синхронизация глобальных состояний

---

#### Process Core
Подсистема управления процессами и CPU-временем.

Функции:
- планирование задач
- управление приоритетами
- распределение CPU-бюджетов
- переключение контекста
- управление состояниями процессов

Характеристики:
- per-CPU runqueue (без глобальных очередей)
- строгая иерархия приоритетов
- бюджетно-кредитная модель
- поддержка добровольной отдачи CPU (`wants_cpu`)

Тип планировщика:
- Per-CPU планировщик с жесткими приоритетами, бюджетированием и перераспределением кредитов


---

#### Memory Core
Централизованный слой управления физической памятью.

Ключевые свойства:
- policy-based allocation
- зональная модель памяти
- детерминированная аллокация
- отсутствие глобальных блокировок

Зоны памяти:
- **Kernel Zone** — ядро и критические структуры  
- **Application Zone** — пользовательские процессы  
- **Service Zone** — системные сервисы  

---

#### Security Core
Центр принятия решений безопасности.

Функции:
- контроль доступа
- аудит
- управление карантином
- реакция на угрозы в реальном времени

---

#### AI Core
Интеллектуальный аналитический модуль.

Функции:
- анализ поведения системы
- прогнозирование нагрузки
- обнаружение аномалий
- помощь Security Core

---

#### Metrics Core
Система телеметрии.

Функции:
- сбор метрик
- передача данных в AI Core и Optimize Core

---

#### Optimize Core
Адаптивная оптимизация системы.

Функции:
- динамическая балансировка нагрузки
- NUMA-aware распределение ресурсов
- оптимизация производительности в реальном времени

---

## 3. Режимы работы системы

- **MONO**  
  Минимальная конфигурация, максимальная предсказуемость  

- **DISTRIBUTED**  
  Полная параллельная обработка и высокая отказоустойчивость  

- **EMERGENCY**  
  Приоритет производительности над изоляцией  

---

## 4. Plants — изолированные домены

Система разделена на изолированные сервисные домены (**Plants**):

| Plant     | Назначение                          |
|-----------|-------------------------------------|
| Plant 1   | Сеть, I/O, драйверы                 |
| Plant 2   | Пользовательские приложения, GUI    |
| Plant 3   | Системные сервисы                   |
| Plant 4   | Песочница / карантин                |

---

## 5. FlexIPC

Безопасная межмодульная коммуникационная шина.

Особенности:
- mTLS
- шифрование
- zero-trust модель
- строгая изоляция взаимодействий

---

## 6. OmniumFS (OFS3)

Современная файловая система.

Особенности:
- объектная модель хранения
- версионирование
- проверка целостности
- высокая устойчивость к сбоям

---

## 7. Многоуровневая система защиты

Security Core управляет **6 уровнями защиты**:

1. **Aethis Layer** — сетевой периметр  
2. **Phantom Layer** — обман и ловушки  
3. **Voltbreaker Layer** — активное вмешательство  
4. **Ironveil Layer** — защита ядра и памяти  
5. **Shadow Bastion** — скрытые пространства  
6. **Core Sanctum** — финальная защита ядра и OFS3  

---

## 8. Архитектурная классификация

- Hybrid Kernel Architecture  
- Zone-based Memory Management  
- Policy-driven Resource Allocation  
- Integrated Multi-layer Security OS  
- Platform-oriented Operating System  

---

## 9. Общая концепция

**Omnium OS** — это система, где:

- планирование
- память
- безопасность
- хранение данных

представляют собой **единую архитектуру**, а не набор разрозненных подсистем.

## Сборка и запуск

Нужны `nasm`, `grub-mkrescue` (пакеты `grub-pc-bin`, `xorriso`, `mtools`) и `qemu-system-i386`.

```bash
make                 # собрать omnium.iso (кросс-компилятор i686-elf-gcc)
make CROSS=          # то же самое обычным gcc на Linux
make run             # запустить в QEMU, вывод ядра идёт в терминал
make run SMP=4       # 4 ядра
make test CROSS=     # загрузка без окна + проверка лога (serial.log)
make unittest        # проверка планировщика на обычном компьютере
```

Что видно при загрузке: проверка зон памяти, тест карантина Security Core,
запуск второстепенных ядер (AP) и тики таймера.

## Эмулятор OmniumCPU и язык Flang

Папка [`emulator`](emulator) — эмулятор процессора OmniumCPU на Python и компилятор языка Flang.

```bash
cd emulator
python3 main.py              # скомпилировать и запустить test.fx
python3 -m pytest tests      # тесты компилятора и эмулятора (pip install pytest)
```

Свою программу можно запустить, поменяв `SOURCE_FILES` в `main.py`.
